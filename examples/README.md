# Sprint Examples

These examples show how to turn a broad idea into a bounded sprint with observable tests. Choose the closest project shape, then use it to fill the repository's root [`03-SPRINT.md`](../03-SPRINT.md).

| Example | Use it when your project is mainly about | Primary output |
|---|---|---|
| [Public-source playbook](01-public-source-playbook/SPRINT-example.md) | research, synthesis, guidance, or writing | a cited Markdown playbook |
| [Website quality review](02-website-quality-review/SPRINT-example.md) | inspecting a local website without changing or publishing it | a prioritized review report |
| [Public CSV cleanup](03-public-csv-cleanup/SPRINT-example.md) | cleaning or validating non-sensitive tabular data | cleaned CSV, data dictionary, and validation report |

## How To Use An Example

1. Read the example and identify what must change for your project.
2. Put your authorized, public or non-sensitive source files in the root `context/` directory.
3. Edit the root `03-SPRINT.md`; do not run directly from an example directory unless you deliberately change every path.
4. Give the agent `prompt.md`.
5. Review the proposed sprint contract before saying `CONTINUE`.

Examples are patterns, not authority. Replace their audience, deliverables, sources, tests, boundaries, and acceptance task with facts appropriate to your project.
